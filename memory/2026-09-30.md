### 1. 归因：把“哪个动作不行、被谁挡的”写清楚
- 新增 `lockers_with(r, need, out, n)`：把占用进程聚合成“X(PID 1)、Y(PID 2)”；
  `need` 传 NULL 收全部，传“写”/“删” 只收对应权限的
- `diag_windows` 归因（访问权限→人话）：
  - 有【写】权限的 N 个 = 无法保存/覆盖的直接原因
  - 持【删除】权限的在做删除/改名
  - 全是【只读】→ 不影响读，但仍挡删除（句柄未共享删除时）
  - `canWrite=0` → “写入/保存被挡住 ← X(PID a)、Y(PID b)”
  - `canDelete=0` → “删除/改名被挡住 ← 全部占用进程（Windows 任何占用都挡）”
  - 非进程占用时明确写“非进程占用（只读属性/权限不足/只读挂载）”
- `diag_posix` 新增一行：`操作影响：读取 ✓ ｜ 写入 ✓ ｜ 删除/改名 ✓`
- 界面占用进程表新增影响标签：影响写入(红)/影响删除(黄)/仅读取(绿)，带 hover 说明

## 经验
- **规则打分靠“命中关键词个数”**，宽泛关键词（如 rule 1 的 `in use by`）会跟具体规则抢首位。
  解决办法是给具体规则加更长的复合关键词（如 `document is in use by another application`），
  用命中数把排名顶上去——比调权重更省事

### 危险操作二次确认（原生 confirm → 自定义弹窗）
弹窗固定三段：**影响面**（目标/类型/大小/当前占用进程）+ **风险清单** + **更稳妥的替代做法**。
改造的入口：结束进程、释放占用、删除、强力清除、清空历史。
- 结束进程额外显示：它持有的文件、句柄访问权限；替代做法是「改用释放占用」
- 所有文本走 `textContent`/`esc()`——路径与进程名是不可信输入，绝不拼 innerHTML
- ESC / 点遮罩 / 取消都可退出

### 技术笔记
- **`write`/`edit` 工具会把 shell 里的 `$(...)` 改写成 `***`**（见 09-29 记录）。
  本次在 JS 里用 `$("\u0061")` 这类元素选择器没受影响，受影响的是 `smoke_test.sh` 里
  新增的 `BATCH=$(T ...)`——但这次居然写对了；真正踩坑的是编辑时把 `fi` 重复了一份。
  **结论：改 shell 脚本后必须 `bash -n` 自检**
- CSV 的 UTF-8 BOM 用 `"\ufeff" + ...` 即可，`JSON.stringify` 不转义 U+FEFF，
  肉眼看不出来，要按字节验证（`EF BB BF`）
