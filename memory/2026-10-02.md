## 本轮：批量检测入口 + Windows 右键菜单对齐（commit b2745b6）

### 1. 批量检测改为可粘贴触发
**发现的问题**：批量检测只在「拖入多个文件」时触发，粘贴多个路径会被当成**单个**路径
送检，拼在一起必然“路径不存在”——功能等于不可发现。
- 路径输入框 `input` → `textarea`：**多行粘贴 = 批量检测**
- `runScan` 自动分流：多行走 `runBatchPaths`（直接送 /api/scan-batch，>24 项自动截断），
  单行走原流程
- 回车：单行仍是“回车即检测”（保留习惯）；多行 Enter 换行、Ctrl/Cmd+Enter 检测
- CSS 给 #pathInput 加 `resize:vertical; min-height:46px`

### 2. Windows 右键菜单与 macOS 对齐
原来 `exe "%1"` 弹命令行黑框；macOS 快速操作用的是 `--open` 直达界面，不一致。
改为两条：
- 「用 filelock 查占用（打开图形界面）」→ `exe --open "%1"`
- 「用 filelock 生成报告（命令行）」→ `exe "%1"`
三类位置（文件/文件夹/文件夹背景）各一套，卸载成对清理。
重构出 `add_menu_items()`，消掉三段重复注册表代码。

## 经验
- **功能做出来了不等于用户能发现**。批量检测代码早就在，但入口只有拖拽——
  这类“隐藏功能”要么给显式按钮，要么顺着用户的自然输入习惯（粘贴多行）触发
- 改控件类型（input→textarea）要连带回车语义一起想：
  单行输入的“回车即提交”在多行场景下会误伤，得分流

### 修 Makefile 交叉编译断链（verify.sh 跑出来的真问题）
**`tools/embed_web` 是构建机上跑的工具，之前用 `$(CC)` 编** →
`make clean` 后交叉编译会用 mingw 编出 Windows 版 embed_web，Linux 上跑不起来，
整个构建直接断（Error 127）。
修：新增 `HOSTCC ?= cc` 专供打包工具，交叉编译从干净树也能跑通。

## 教训
- **交叉编译项目里，构建期工具必须用 HOSTCC，不能用 CC**。
  平时没暴露是因为 web_embedded.h 没重新生成，一旦 `make clean` 就现形
- 测试要覆盖「文件状态」而不只是内存状态：截断那条特意读文件数行数，
  否则内存里截断了、文件还在涨，测试照样绿
