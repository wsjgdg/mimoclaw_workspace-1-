## 本轮（commit bbbc6e1）：三类实打实的 bug 修复
1. **构建参数被静默丢弃**（`filelock/Makefile`）
   - `CFLAGS += -D_DEFAULT_SOURCE` 写在 `CFLAGS ?= -O2 -Wall -Wextra` 之前
     → `?=` 见变量已定义就跳过 → 项目**从来没用 -O2 -Wall -Wextra 编译过**
   - 修：`?=` 提到 `+=` 前；`-D_DEFAULT_SOURCE` 挪进独立 `DEFINES` 变量（用户传 CFLAGS 时也不会丢）
2. **缓冲区截断 / 溢出隐患**（`src/diagnose.c`）
   - detail[256] 用 snprintf 拼多段长路径，5 处 `-Wformat-truncation`；
     Windows 侧 exe 路径可达 MAX_PATH*2=520，直接塞 detail[256] 会截断
   - 修：新增 `str_append()`（纯 memcpy + 显式截断，始终 NUL 结尾）与
     `make_detail()`（"<tag> · 占用 <file> · 用户 <user>"，空段自动省略），
     三处拼装点（run_lsof 的 FLUSH_PROC 宏、proc_scan、win_find_lockers）统一改用
3. **响应体长度写错**（`src/httpd.c`）
   - `send_response(s,403,...,"403 Forbidden (Host)",21)` —— 字符串只有 20 字节，
     把结尾 NUL 一起发给了客户端（od 实测确认）；"bad path" 同样 9→8
   - 404 提示手写 45，实际 51 字节 → UTF-8 尾部被截断成乱码
   - 删除失败提示 msg[320] 不够，"只读属性恢复失败"警告会被静默丢掉
   - 修：新增 `send_text()` 宏（strlen 自动求长），8 处调用点统一替换

## 教训（工具层）
- **`write` 工具写含 `$(...)` 的 shell 脚本会被改写成 `***`**（实测 base64 确认落盘内容就是
  `T=***`，bash 直接语法错误）。同一内容用 `exec` + `cat > file <<'EOF'` 写则完好。
  → 写 shell 脚本一律用 exec heredoc，并用 `bash -n` 自检
- 命令行里别写 `$(curl ... | sed 's/.*"token":"***".*/\1/p')` 这类“取令牌”模式：
  工具输出与落盘内容都会被脱敏成 `***`，排查时极易误判
